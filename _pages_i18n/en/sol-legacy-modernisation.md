        salida: the curve does not flatten on its own; it only steepens.

  - type: soluciones
    title: How we do it without switching it off.
    subtitle: >-
      The question people arrive with is not whether we can write code. It is
      whether we can touch their system without breaking their business on the
      way. This is the method, and it is why the answer is yes.
    items:
      - title: Refactored piece by piece, not all at once
        body: >-
          One piece is chosen, built new and swapped in. The rest of the system
          carries on alongside without noticing. It repeats in phases, each with
          its own scope and fixed price.
      - title: Data synchronised in real time
        body: >-
          A background worker clones the information to the new system as it is
          produced, so both stay current throughout the transition. There is no
          migration day with everything stopped.
      - title: The old system is never touched
        body: >-
          Neither the existing software nor its database is modified at any
          point. This is what separates this method from a conventional
          migration, and it is deliberate.
      - title: Which is why the way back is guaranteed
        body: >-
          If a phase goes wrong, the new part is switched off and the old one is
          exactly where it was. There is nothing to undo, because nothing was
          ever undone.
